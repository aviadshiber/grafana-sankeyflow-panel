# Contributing to SankeyFlow

Contributions are welcome across code, tests, documentation, examples, and issue triage.

## Workflow

1. Search existing issues and documentation.
2. Open an issue for a substantial behavior change or design question.
3. Create a focused branch and make the smallest coherent change.
4. Add or update tests and user-facing documentation.
5. Run the relevant checks from [development.md](docs/development.md).
6. Open a pull request using the repository template.

Do not include generated credentials, signed artifacts, customer data, or unrelated formatting changes. Changes to the public data contract must update `docs/data-model.md` and `CHANGELOG.md`.

## Pull request expectations

A good pull request states the problem, summarizes the solution, identifies compatibility impact, and includes verification evidence. Reviewers may ask for a smaller scope, stronger diagnostics, accessibility coverage, or documentation examples.

## Community standards

Participation is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Security issues must follow [SECURITY.md](SECURITY.md). The project’s decision-making and maintainer roles are described in [GOVERNANCE.md](GOVERNANCE.md).
